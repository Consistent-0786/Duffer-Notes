# Why Automate ?

- It reduce **manual work** for SOC analysts    
- Respond to incidents **faster and consistently**    
- Improve overall **SOC operations**
-  Security Automation is not **Isolating machines only**, 
    - Isolation can be part of automation
    - But automation is **much broader**
- It basically **Mimicking the steps an analyst would take**      
    - Investigation steps
    - Enrichment
    - Notifications
    - Response actions

## Positive Impact of Automation

- **Mean Time to React (MTTR)**    
    - Immediate automated responses
        
- **SOC Efficiency**    
    - Less manual effort        
    - Analysts focus on real threats
        
- **Cost Reduction**    
    - Faster resolution = lower operational cost
        
- **Standardized Incident Responses**    
    - Same actions every time        
    - No analyst-to-analyst differences

# Automation Capabilities in Sentinel

1. **Automation Rules :**
	- Basic automations
    - Used for **initial triage**

- **Examples :**    
    - Assign incidents        
    - Change severity        
    - Add tags        
    - Trigger playbooks

2. **Playbooks :**
	- Used for complex automations
	- Part of **SOAR** 
	- Use **Azure Logic Apps**

- **Examples :**
    - Enrich incidents  
    - Notify teams        
    - Take response actions across systems
