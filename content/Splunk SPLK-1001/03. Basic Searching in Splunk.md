# Search with Keywords and Phrases
## Keyword

- Used to search **single or multiple separate words** in all indexes
	- For **Example :** 
		- `ubuntu` - searches for the word _ubuntu_ anywhere
	    - `amanda` - searches for the word _amanda_         
	    - `user ubuntu` - searches for both _user_ and _ubuntu_ (they can appear separately in the same event)
## Phrase

- Used to search **combined or exact word sequences**, enclosed in **double quotes (" ")**
	- For **Example :**
		- `"user ubuntu"`- searches for the exact phrase _user ubuntu_ (words appear together in this order)
## Note 
- By Default , the user (admin) can only search in main index without specifying it 
- To make the index searchable , **follow the steps below :**
	1. Go to settings -> User and Authentication -> roles -> double click user **"admin"** -> Indexes tab
	2. Scroll down -> Default tab on right hand side -> select the index you want to make searchable by default -> Tick on the Index to make it appear in the Default tab

# SPL Language Components

## 1. Commands

- Commands tell Splunk _what action to perform_ on the events retrieved by your search terms. 
- Examples: `eval`, `top`, `rename`, `sort`, `table`
- **Commands can :** 
	- Calculate statistics
	- Create new fields
	- Filter results
	- Format output
## 2. Functions

- Functions are used _inside commands_ (especially inside `eval` or `stats`) to perform a specific operation
 - Example functions: `if()`, `count()`, `sum()`
 
```
| eval status_flag = if(status=200, "OK", "Error")
```
## 3. Arguments

- Arguments provide additional parameters for commands or functions
- **Example : ** 
	- `limit=10` in the `top` command restricts output to 10 results
## 4. Clauses

- Clauses are modifiers used to group, rename, or refine the results
- **Common clauses :**
	- `BY`
	- `AS`
- **Example:**

```
| stats count BY status
```

- **Commands** → _Blue_ (ex: `eval`, `top`, `rename`)
- **Functions** → _Purple_ (ex: `if`, `count`)
- **Boolean Operators & Clauses** → _Orange_ (ex: `AND`, `OR`, `NOT`, `BY`, `AS`)
- **Arguments** → _Green_ (ex: `limit`, `span`)

# Use Wildcards and Comment
## Correct use of wildcards

Use the asterisk `*` **at the end** of a word  
- **Example :** 
	- `pass*` - matches _pass_, _passed_, _passing_   
	- `fail*` - matches _fail_, _failed_, _failure_   
- This method is efficient because the search starts from the beginning of each word and looks forward
## Incorrect use of wildcards

1. **At the beginning of a word**  
    - **Example :**
	    - `*fail` ,`*word`
    - This makes the system scan every character in every event to find matched 
    - It is inefficient and can reduce search performance

2. **In the middle of a word or string**  
    - **Example :**
	    - `http*buttercupgames.com`
    - This can return inconsistent results if the string includes punctuation such as `:`, `/`, or `.`
    - It also makes the search slower and less reliable or the search will not execute

## How to Comment a line 
- To comment a line / multiple lines use :
```
Use Backtick -> ``` Command / Commands ``` and same for multiple lines 
```

# Use Boolean Expressions
## Using Boolean operators in searches

- Use **Boolean operators** **`AND`, `OR`, `NOT`** to combine or exclude search terms
- **Operators must be in uppercase** so the system recognizes them correctly
## AND operator

- The `AND` operator is implied between search terms 
- You do not need to type it explicitly as it is applied by default
- **Example :**
	- Searching for `failed password` is the same as **`failed AND password`**
- This returns results that include both words
## NOT operator

- The `NOT` operator applies only to the term immediately following it
- **Example :**
	- `user NOT administrator`
- Returns results that contain the word `user` but do not contain the word `administrator`  
## OR operator

- Use the `OR` operator to search for either one term or another    
- It is best practice to enclose OR searches in parentheses `(keyword OR keyword)`
- **Example :**
	- `(error OR failure)`
- Returns results that include either `error` or `failure`

# Setting Search Time Range 

- In Splunk, you can set **time ranges** in the **Time Range Picker** to control what data your search uses
## Types of time ranges

- **Real-time** - shows data as it comes in eg = 1min , 5 min , 15 min , etc
- **Relative** - looks back a set time from now, like the last 24 hours
- **Date Range** - pick start and end dates
- **Date & Time Range** - pick specific dates and times
- **Advance** -  you can use **time modifiers** to manually set custom ranges
## Search Time Command Operator

- To search in a Specified Time range , `earliest=Time latest=Time` operators are used to set the time / date - time range
- **Example :**
1. This searches events from the last 24 hours
```
index=security earliest=-24h latest=now
```

2. This searches data from the last 2 days up to the current time
```
index=security earliest=-2d latest=now
```

3. You can also enter **absolute times** in date and time format
	- This searches data between November 10, 2025, 00:00:00 and November 12, 2025, 23:59:59
	
```
index=security earliest="11/10/2025:00:00:00" latest="11/12/2025:23:59:59"
```

- ==**@ symbol**== snaps time to the nearest unit  in `h` (hours) 
- **Example :**
	- If the current time is 10:42, this looks back to 06:00 exactly
```
earliest=-4h@h latest=now
```
## Time units 

`s` = seconds  
`m` = minutes  
`h` = hours  
`d` = days  
`w` = weeks  
`mon` = months  
`y` = years

# Comparison Operators 

| Operator | Description                         | Example                                                            |
| -------- | ----------------------------------- | ------------------------------------------------------------------ |
| `=`      | Equal to                            | `status="200"` → finds events where status is 200                  |
| `!=`     | Not equal to                        | `status!="404"` → finds events where status is not 404             |
| `<`      | Less than                           | `bytes<1000` → finds events where bytes are less than 1000         |
| `>`      | Greater than                        | `bytes>5000` → finds events where bytes are more than 5000         |
| `<=`     | Less than or equal to               | `duration<=30` → finds events where duration ≤ 30                  |
| `>=`     | Greater than or equal to            | `duration>=60` → finds events where duration ≥ 60                  |
| `LIKE`   | Pattern match using wildcards (`*`) | `user LIKE "admin*"` → finds users starting with “admin”           |
| `IN`     | Match any value in a list           | `status IN (200,404,500)` → finds events with those status codes   |
| `NOT IN` | Exclude values in a list            | `method NOT IN ("GET","POST")` → finds methods other than GET/POST |
## Note 
- Fields are case sensitive but values are not case sensitive 
- **Example :**
	- For Fields :
		- `action=true` `->` Correct 
		- `Action=true` `->` Not Correct
	- For Values: 
		- `action=true` `->` Correct
		- `action=True` `->` Correct
		- `action=TrUe` `->` Correct
