# Splunk Components Overview

- Splunk is made up of multiple components that handle data collection, indexing, searching, and system management
- These components are divided into **Two main categories :**
	1. **Processing Components** 
		- handle the data flow and user interaction
    2. **Management Components** 
	    - control, monitor, and manage configurations and licenses
## 1. Processing Components

These components are responsible for getting data into Splunk, storing it efficiently, and allowing users to search and visualize that data.
### Forwarders

- Forwarders are the first step in the data pipeline, ensuring that data from different sources reaches Splunk safely and efficiently
- Forwarders are Splunk agents installed on source machines (like servers, network devices, or applications) to collect and send data to indexers

 - **Types of forwarders :**
	- **Universal Forwarder (UF) :**  
	    - A lightweight version of Splunk used only for forwarding raw data to indexers 
	    - It doesn’t index data locally, which makes it efficient and suitable for production servers
	- **Heavy Forwarder (HF) :**  
	    - A full Splunk instance that can parse, filter, and route data before sending it to indexers
	    - It’s used when you need to preprocess data (for example, masking sensitive fields or routing different logs to different indexers)
	    - This reduces load on **Indexers** as they now no need to parse the data    

---
### Indexers

- Indexers are the core of Splunk’s data processing 
- They receive data from forwarders, store it in indexes (storage nodes), and make it searchable
- **Key roles of an indexer :**
	- Parses and indexes incoming data
	- Stores data in structured indexes
	- Handles search requests and retrieves results
	- Maintains high performance for data queries and dashboards

- In a large environment, multiple indexers can form an **Indexer Cluster for :**
	- Load balancing
	- Data replication
	- High availability (so if one indexer fails, another can serve the data)

---
### Search Heads

- Search Heads allow users to interact with indexed data through searches, dashboards, and reports
- **Functions :**
	- Run search queries and generate visualizations
    - Provide user interfaces for Splunk Enterprise and Splunk Web
    - Manage alerts, scheduled reports, and dashboards

- In bigger deployments, multiple search heads form a **Search Head Cluster (SHC)**
	- This cluster allows multiple users to search simultaneously without delays.
	- **Example of Search Head Cluster:**
		- Search Head (SH1) runs a search query
	    - SH2 and SH3 share results and load
	    - All search heads stay synchronized so users get faster responses without waiting
	    - This setup improves reliability and distributes the workload efficiently

---
## 2. Management Components

- Management components control, coordinate, and monitor the Splunk environment
- They help administrators manage large or distributed Splunk deployments
### Deployment Server

- Used to manage configurations for multiple forwarders at once
- Instead of updating each forwarder manually, the **Deployment Server** pushes new apps, configurations, or updates to all connected forwarders automatically

---
### Indexer Cluster Manager

- Splunk indexer cluster is a group of Splunk Enterprise indexers configured to replicate data, ensuring high availability and disaster recovery by maintaining multiple copies of data across all indexers
- Indexer Cluster Manger write data to Indexes (which are storing Disks) according to Index Storage Paths Repositories  
	-  ==Indexer Cluster Manger -> Indexes -> Index Storage Paths Repositories==
#### 1. Indexes

- **Indexers** stores data in ==indexes==
- Indexes are the logical data stores in Splunk
- All the data Splunk receives is stored in indexes, which act like databases
- **Common index types :**
	- **main :** The default index used for most incoming data
    - **_internal :** Used by Splunk to store its own logs and metrics (like system health)
    - **custom indexes :** Created by users or apps for organizing specific data sources separately
##### 1.1 Index Storage Paths Repositories

- Splunk manages indexed data in different storage paths based on its age and usage
- Data automatically moves from Hot → Warm → Cold → Frozen over time -> Thawed Path

- **Index Storage Paths Repositories: **
	1. **Hot Path:**
	    - Newly indexed data that is still being written to
	    - Active data stored in memory for fast access
	2. **Warm Path:**
	    - Data that is no longer being written but is still searchable
	    - Moved here after the hot buckets fill up
	3. **Cold Path:**
	    - Older data, still searchable but less frequently accessed
	    - Stored on cheaper disks
	4. **Frozen / Archived Path:**
	    - Very old data that is moved out of Splunk storage
	    - Can be deleted or archived manually
	5. **Thawed Path:**
	    - Archived (frozen) data that is restored for searching again
	    - Used when old logs need to be analyzed later

### Search Head Cluster Deployer

- It manages and pushes configurations, apps, and updates to all search heads in the cluster 
- This ensures that all search heads remain consistent and use the same settings

---
### License Manager

- Controls licensing for the entire Splunk deployment
- It ensures that the organization stays within the licensed daily data volume
- **The License Master :**
	- Tracks how much data is indexed daily
	- Ensures compliance with license limits
	- Distributes license information to other Splunk components

---
### Monitoring Console (MC)

- The Monitoring Console is one of the most important tools for Splunk administrators
- The Monitoring Console provides a ==centralized view of Splunk’s health and performance==
- It helps administrators identify performance issues, bottlenecks, or indexing delays
- **Main uses :**
	- Monitors search head and indexer performance
	- Tracks system resources (CPU, memory, I/O)
	- Displays license usage and data ingestion rates
	- Provides visual dashboards for easy health monitoring
