
# Macros 

- Macros are ==**reusable snippets** of Splunk Search Processing Language (SPL) that simplify complex searches==, making them modular and easier to maintain, much like functions in programming
	- Macros are useful for frequently run searches or reports with similar syntax
	- You can define **one or more arguments** to use with the macro at search time
	- Macros can represent the full search string or a portion of a search that can be reused in multiple places
	- Macros are not saved with **time range** , Time range needs to be selected at execution time

## Note : 

> **Macros must be defined in backquotes `` character** 
> To **view Content of Macro** use :
> 	-> Ctrl + Shift + E
> If Using 1 ,2 ,3 ,etc Arguments make sure to add **Argument Number in Macro_Name**, eg =
> 	-> Name : CountPercentError(3) 
> Define Argument in **same order during Execution of code in search** as named 

- **Syntax :**
	- defining macro

```spl
`macro_name`
```

- defining macro with **Arguments**

```spl 
`macro_name(arg1,arg2,arg3...)`
```

## To Create a Basic Macro

- Go to **Settings -> Advance search -> Search macros**
- Provide a Name with **No parenthesis (arguments)**
- Provide Definition with **all search**

## Creating a Macro Arguments

- macro arguments let you pass **dynamic values (fields, strings, numbers)** into reusable search snippets, defined by naming the macro
- `macro_name(N)` (for N args) and using `$argname$` placeholders in the definition
- call it with values like :
	- `` `macro_name(value1, value2, value3)` ``

- **Example :**
```spl
index=main sourcetype=eventgen
| `CountPercentErrors(SouthEast, 603 , State)'
```

### To Save & Execute Macro Arguments 

#### To Save Macro Arguments

1. Suppose we want to create macro Arguments in the above code

```spl
index=main sourcetype=eventgen
| search eventtype=NorthEast
| stats count as total_Events count(eval(failureCode==480)) as total_480_Errors by eventtype partner
| eval percent_480_Errors=(total_480_Errors/total_Events)*100
| sort -percent_480_Errors
| eval percent_480_Errors=round(percent_480_Errors,3)." %"

```

2. We will Create **3 Arguments** i.e :
	1. `$region$` - Can pass the value of any Region as an argument
	2. `$errorCode$` - Can pass the value of any failureCode to get the count and percentage of errors
	3. `$dimension$` - Cans split count and percentage by different groups , eg = partner , nodeName, City, State, County
	
	- **Example :**

```spl
search eventtype=$region$
| stats count as total_Events count(eval(failureCode==$errorCode$)) as total_$errorCode$_Errors by eventtype $dimension$
| eval percent_$errorCode$_Errors=(total_$errorCode$_Errors/total_Events)*100
| sort -percent_$errorCode$_Errors
| eval percent_$errorCode$_Errors=round(percent_$errorCode$_Errors,3)." %"

```

3. Now we will save this code in **Macro Settings :**
	1. Name = CountPercentage(3) - As Macro contains **3 Arguments**
	2. Surround macro Arguments with`$` symbol
	3. Argument = region, errorCode, dimension - Define Argument in same order during Execution of code in search as named

## Validating Macro Arguments

### Macro Validation Expression

- It is a piece of logic, often an `eval` expression, that determines if an input or argument is valid

### Validation Error Message 

- It is the custom text displayed to the user when that expression evaluates to false or an invalid state

**Example :**
- Suppose we want the **error code value must be a number AND must be 3 digits in length**
	- `isnum($errorCode$) AND len($errorCode$==3`
- The Validation Error Message value 
	- `The eoor Code value must be 3 digits integer`
