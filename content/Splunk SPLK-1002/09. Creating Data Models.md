#  Data Models

- It is ==a hierarchical, semantic mapping of your data, organizing raw indexed data into structured, reusable datasets (objects) for easier searching, reporting, and dashboard creation using the== [Pivot tool](https://help.splunk.com/en/splunk-cloud-platform/manage-knowledge-objects/knowledge-management-manual/9.3.2408/build-a-data-model/about-data-models)
- It encode domain knowledge, allowing users to build visualizations **without writing complex SPL (Search Processing Language)** , by defining **parent/child datasets, fields, and relationships**, making data consistent and accessible for security (ES), IT, and other analytics
- It enables non-technical users to create powerful reports via drag-and-drop

## Components of Data Model

### Data sets 

- Data sets are essentially a **collection of events that share common characteristics and fields**
- These datasets are organized in a **parent-child hierarchy**
- data model is composed of one or more **data-sets**

#### Types of Data sets 

##### 1. Root Data set (parent data-set)

- These are the **main data sets** that start the data model 
- **These Data sets are of 3- types :**
	1. **Event datasets** : 
		- It is defined by simple search constraints (eg = `sourcetype=access_*`)
		- These are the most common type and represent a broad category of events 
	
	2. **Search datasets** : 
		- It is defined by a more complex, arbitrary search string that can include transforming commands, often used when the data doesn't map directly to events 
	
	3. **Transaction datasets** : 
		- Used to group related events that occur over a period (e.g., a complete web session), utilizing the `transaction` command logic

##### 2. Child Data sets 

- These **inherit all fields and constraints from their parent datasets** and apply additional constraints to further narrow down the data 
- eg = an `"HTTP Errors"` child dataset might inherit from an `"HTTP Requests"` parent dataset
