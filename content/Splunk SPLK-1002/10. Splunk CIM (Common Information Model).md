
# Splunk CIM

- **Splunk CIM (Common Information Model)** is a **standard way to organize and name data** in Splunk
- It makes data from different sources look the same, so Splunk apps and searches work easily
	- Normalizes data (same field names, same structure)
	- Lets dashboards, alerts, and apps work across many data sources
	- Saves time writing custom searches
- It Normalize data by **Event Types , Tags**

- **Example :**  
Firewall logs, proxy logs, and IDS logs may look different in defferent vendors , but CIM maps them all to common fields like :
- `src_ip`
- `dest_ip`
- `action`

## Splunk CIM Data Model

- A **CIM data model** is a **structured definition of a specific type of data** in Splunk, built on the Common Information Model
- It groups related events into categories with standard fields so Splunk can analyze them easily
	- Enables fast searches (`tstats`)    
	- Powers **Splunk Enterprise Security (ES)**    
	- Works across **different vendors** automatically    
- Each Data Model contains **tags and fields** used to normalize and associate data to the model
- Details in **CIM Add-On manual :**
	- [How to use the CIM data model reference tables](https://help.splunk.com/en/splunk-enterprise/common-information-model/6.1/data-models/how-to-use-the-cim-data-model-reference-tables)

- **Examples :**
	- **Authentication** – `logins, logouts, failures`    
	- **Network Traffic** – `connections, bytes, ports`    
	- **Endpoint** – `process, file, registry activity`    
	- **Web** – `web requests, URLs, status codes`
